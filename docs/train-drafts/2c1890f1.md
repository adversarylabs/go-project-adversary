## What we want to improve

Detect when changed repository scripts or Makefiles introduce new external CLI invocations (for example jq, node, sphinx-build, wasm-pack) without corresponding edits to recognized prerequisites documents.

## Why this matters

Added external command invocations broaden the project's prerequisite surface and can break local builds or generation steps when contributors lack those tools; surfacing such diffs helps maintainers keep prerequisite docs or vendoring in sync with changed files.

## Examples

- A documentation build script in a Python project is changed to call 'sphinx-build' but the change does not update CONTRIBUTING.md to list 'sphinx-build' as a prerequisite.
- A CI or packaging script for a Rust/wasm project is modified to call 'wasm-pack' or 'node' for bundling and the change omits any edit to recognized prerequisites documentation.

## Keep it focused

- A script change that only invokes POSIX utilities such as grep, sed, awk, mkdir, cp, or test should not be flagged.
- A change that calls a repository-relative binary (for example ./tools/formatter) where the binary is committed in the repository should not be flagged for missing prerequisites documentation.

## Done when

- [ ] If a changed file adds a new external CLI invocation (for example jq, node, sphinx-build, wasm-pack) in a script or Makefile and no changed files update a recognized prerequisites document, emit one issue recommending updating prerequisites or vendoring the tool.
- [ ] If the change that adds an external CLI invocation also updates a recognized prerequisites document (for example CONTRIBUTING.md, PREREQUISITES, or docs/*prereq*) and that document mentions the added tool, do not emit an issue.
- [ ] If the diff only adds invocations of ubiquitous POSIX utilities (for example grep, sed, awk, mkdir, cp, test) or calls a binary via a repository-relative path (for example ./tools/mytool), do not emit an issue.
- [ ] If the added invocation appears elsewhere in the same changed files as a comment or vendoring instruction demonstrating the tool is documented or vendored in this change, do not emit an issue.
